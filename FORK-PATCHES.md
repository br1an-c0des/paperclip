# Fork patches

Every place where the fork changes code that upstream owns, and why. Changes inside fork-only files
(see [FORK.md](FORK.md#fork-only-files)) don't need an entry.

This file is what makes upstream merges safe. A merge can succeed with no conflicts and still break
a fork change: upstream renames a function a hook calls, or changes what a column means. The
`upstream-sync` skill reads each entry, checks upstream's changes against it, and uses the stated
intent to resolve conflicts. So keep entries current: add one in the same commit as the change, and
update it whenever a merge moves or rewrites the patch.

## How to add a patch

Prefer, in order (details in [FORK.md](FORK.md#changing-server-database-and-packages)):

1. **A plugin.** No entry needed: plugins live in fork-only directories.
2. **New files plus a small hook** in an upstream file. Mark the hook with a `FORK:` comment
   (`// FORK: <entry id>` in code, `# FORK: <entry id>` in YAML) and add an entry here.
3. **Editing upstream logic directly.** Last resort. Same marking and entry, and say in **Why**
   why a hook wasn't enough.

## Entry format

```markdown
### <entry id, kebab-case>

- **Files:** upstream files changed (fork-only files the patch adds, if any, in brackets)
- **What:** the change, in one or two sentences
- **Why:** what the fork needs it for
- **Depends on:** upstream names or behaviour the patch relies on (functions, tables, routes,
  config keys). The sync agent checks upstream's changes against these.
- **If upstream changes this:** how to resolve a conflict or breakage, and what must stay true
```

## Code patches

### workspace-ui-new

- **Files:** `pnpm-workspace.yaml`
- **What:** adds `- ui-new` to the workspace package list.
- **Why:** makes `ui-new` a workspace package so it can import `@paperclipai/shared`.
- **Depends on:** the `packages:` list in `pnpm-workspace.yaml`.
- **If upstream changes this:** keep upstream's version of the file and re-add the `- ui-new` line
  to the `packages:` list. Order doesn't matter.

### lockfile

- **Files:** `pnpm-lock.yaml`
- **What:** the importer entries caused by the `ui-new` package.
- **Why:** generated by pnpm from [workspace-ui-new](#workspace-ui-new).
- **Depends on:** nothing by hand.
- **If upstream changes this:** never resolve by hand. Take master's version and regenerate:
  `git checkout --theirs pnpm-lock.yaml && corepack pnpm install && git add pnpm-lock.yaml`.
