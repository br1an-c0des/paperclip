## Upstream changes

**175 upstream commits** (`3ef45fdd9..bf0220d34`, 2026-11-09 – 2026-11-10)

### What this batch is mostly about

Most of the batch is server-side hardening again:
- restart and storage-outage recovery: runner, native, recovery, heartbeat and storage fixes;
- about 35 performance commits;
- 29 chaos and eval test commits. The chat catalog eval harness (#19614) alone is a third of the 1,680 changed files.

The board-facing changes centre on the task's interruption notice:
- the board can now confirm that an unidentified run stopped;
- a new original-host "containment" form;
- every Retry either starts work or says why;
- a budget-held Retry stays visible;
- a failed workspace setup command and a rejected model are named.

Also board-facing:
- app approvals survive OAuth refresh, with a new "Approved · Sign-in needed" state;
- queued messages show Markdown and screenshots;
- agent roster filters;
- per-agent interaction permissions (API and CLI only).

### Larger new features

- **Confirm an unidentified run stopped** (`8fe524f79`, #20310). Some native runs were cut off after asking to start the runner, before the runner's process was recorded. Until now a Retry on them waited forever (`process_identity_missing`).
  - The task now presents `state: "waiting_for_user"`, `userAction: "confirm_run_stopped"` and `canRetry: false`, with an explanation.
  - An owner or admin (`runtime:confirm_owner_stop`) confirms how they checked: `POST /issues/:id/recovery-actions/confirm-run-stopped`, body `{runId, stopEvidence}` (20–12,000 characters).
  - The answer is `{runId, alreadyStopped, presentation}`. The parked Retry then starts at once.
  - The old UI's `ExecutionBlockerNotice` reuses `PreviousServerStopConfirmation` (now with optional `action`, `runId`, `formId` and custom copy) and offers "Confirm it stopped". It logs `issue.run_stop_confirmed`.
  - It also stops a restore hold from blocking the same agent's Retry after a system-interrupted preparation.
- **Original-host containment for native recovery** (`a3e7e6333`, #19813). Recovery now records and verifies the controller's process namespace, and keeps foreign or unknown ownership held.
  - It applies to a board-owned `active_run_watchdog` with cause `native_restart_recovery_blocked` and `evidence.reason: "controller_process_space_unverified"`.
  - The old UI shows a new `NativeControllerContainmentRecovery` card on the task: "Verify the original execution stopped". It has two confirmation checkboxes (controller, and provider with its tools), the reviewed action outcome (completed, not performed or mixed) and evidence.
  - It posts `resolveRecoveryAction` with `outcome: "restored"` and `executionReconciliation: {runId, controllerStopped: true, providerStopped: true, controllerAuthorityDigest, actionOutcome, outcomeEvidence}`. The digest comes from `evidence.controllerAuthority.digest` and is never typed in.
  - Recording containment doesn't retry: Retry stays a separate step.
- **Every Retry starts work or says why** (`ef2b8d532`, #20283; `93f7c3b5d`, #20338).
  - A Retry during a scheduled retry's countdown now promotes that run. `POST /issues/:id/retry` answers `scheduledRetry: {outcome, message}`, with outcomes `promoted`, `already_promoted`, `gate_suppressed`, `waiting` or `no_scheduled_retry`.
  - A stale or not-started Retry shows its reason. The old Inbox no longer navigates for it.
  - "Retry now" (`/scheduled-retry/retry-now`) now needs task read and `issue:mutate`: a private task answers 404.
  - A Retry held by a budget hard stop presents `waiting_for_user` with `userAction: "budget"`. The old UI says "Couldn't finish this attempt. Your message is saved. It is waiting for the budget to allow new work. Raise the budget in Costs."
  - An open page refreshes through a new `issue.execution_waiting` activity, logged when a deferred request's wait reason changes.
- **Approved app calls survive OAuth refresh and slow review** (`c67909cb0`, #20340).
  - Ordinary app-action reviews no longer get an implicit one-hour deadline: `RequestConfirmationToolActionPayload.expiresAt` is now `string | null`.
  - An approved call whose connection needs signing in again is kept: `result.toolAction.status: "approved"` with `errorCode: "approved_action_connection_required"`. The card reads "Approved · Sign-in needed" with "Reconnect <app>", linking the app's permissions tab.
  - New refusal codes: `approved_tool_target_changed` and `approved_tool_managed_arguments_changed`.
- **Individual agent interaction permissions** (`5bad074ba`, #20411; docs `b6f4008f9`, #20422).
  - Eleven sparse, deny-only switches are stored under `agent.permissions.interactions`. Examples: `canAssignTasksToAgents`, `canReceiveAssignmentsFromAgents` and `canEditOtherTasks`. Each defaults to allowed.
  - Read and set them with `GET` and `PATCH /agents/:id/interaction-permissions` (board only; `null` resets a switch). The answer is `{agentId, companyId, overrides, effective}`.
  - `PATCH /agents/:id` and `/agents/:id/permissions` now refuse any `permissions.interactions` (422).
  - Only the CLI and API offer them; the old UI has no screen.
- **Single agent permission grants** (`ff2d463ee`, #20323): `PATCH /agents/:id/permission-grants` with `{permissionKey, enabled}` (board only), plus `agent permission:grant` and `agent permission:revoke` in the CLI. The old UI doesn't use it.
- **Agent roster filters** (`98f49af70`, #20317): model, status, harness and connection filters on the old Agents page (both layouts, org chart included). Each filter has All and an active count, and bulk selection survives hidden rows.
- **Named failures on the task page.**
  - A workspace setup command that exits non-zero is named (`a14ae9b5c`, #20478). The field is `interruption.setupFailure {step, command, exitCode, output, message}`, and the notice reads "Couldn't set up the task workspace. <message>. Fix the command in the project's workspace settings, then retry."
  - A rejected model is named (`82abb3ea0`, #20488): `interruption.rejectedModel` with `userAction: "choose_model"`.
  - Generic `adapter_failed` runs get `failureCause`, such as `40001` or `ECONNRESET`, and the run ledger shows "adapter failed (40001)". SQL statement text is now stripped from errors the board sees (`1e13c58a4`, #20483; shared `run-failure-cause.ts`).
- **Queued setup repair through the task's connection card** (`b09f17fbf`, #20361).
  - Verification that fails on a missing AI account default now parks instead of retrying every minute.
  - The task gets a `connection_intent` card with `agentSetup: true` and `agentSetupOperationId` (purpose `ai`). Completing it rechecks verification and releases the queued turn.
  - The old UI hides its "is paused / Resume" banner while the agent has no `pauseReason` and is `preparing`, `verifying` or `resuming`.
- **Queued messages show Markdown and screenshots** (`eebdfe71b`, #20367). Each queued row renders Markdown with images left out, plus up to three thumbnails of `/api/attachments|assets/:id/content` images and "+N" for the rest.
- **A chat message is held at the agent's daily limit instead of dropped** (`d10c6e0e8`, #20292). It waits in the outbox: the queue is `deferred`, with no queue id or target run, and its `executionWait.message` says why.
- **Storage outages are waited out, not failed** (`4a2eb920c` #20299, `693de27c9` #20456, `34c1e6469` #20313, `15a734d06` #20460).
  - A run's critical path waits through an object-store outage, and through expired or rotated S3 credentials.
  - The wait shows as live run status: phase `waiting_for_storage` (new in `HeartbeatRunStatusPhase`), with "Waiting for file storage before starting the run log (45s so far)". One lifecycle warning is recorded when it ends.
- **Codex and Claude sign-in on plugin agent computers** (`3a5572c9e` #20410, `8809f44b5` #20417).
  - The sandbox sign-in panels now also work on a saved agent's computer from an environment plugin: `agentId` on the login-session requests, and `EnvironmentCapabilities.loginPtyDrivers`.
  - The new `environmentSupportsLoginPty` helper and the old UI's `AgentLoginTarget` "Sign-in computer" picker go with it.
- **Moving an agent to a plugin environment pauses it automatically** (`1838de8c6`, #20375). Saving the move used to answer 409 "pause, change, resume". Now it pauses, waits for the stop, starts the plugin's resources and verifies.
- **Faster task opens** (`1baac2788` #20355, `189fefb99` #20286, `7329eaf35` #20450, `7e93ccb4b` #20389).
  - New `GET /companies/:companyId/issues/chat-bootstrap?ids=` (up to 10) and `GET /issues/:ref/chat-bootstrap` return the whole first frame of the task chat in one read.
  - The old UI preloads it on hover and from Recents.
  - `ISSUE_SUMMARIES_MAX_IDS` goes from 5 to 50.
  - Workspace summaries accept `?ids=` (up to 100; #20388).
- **The parent task in the old UI's breadcrumbs** (`cac82ed4d`, #20366). The breadcrumbs now show the immediate parent, with responsive truncation; a private parent shows as a non-interactive lock chip.
- **GitHub star prompt** (`a5e01634f`, #20453). On self-hosted instances only, after 5 done tasks in a company, a dialog asks once per browser to star the repository on GitHub.
- **Workspace archives** (about 20 workspace commits, server only):
  - saved files are read from the archive in place (#20442);
  - identical captured archives are reused (#20476);
  - migration uses one archive with no readback (#20554);
  - migration sources and recovery are protected (#20443, #20424, #20436, #20416, #20441, #20371).
