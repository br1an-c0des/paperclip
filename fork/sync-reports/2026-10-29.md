## Upstream changes

About a third of the batch (≈63 `fix(server)` commits) moves background work off heartbeat polling.
Work now wakes from committed changes and saved deadlines. The board-visible part:

- the opt-in Coordinator workspace;
- the agent YAML editor;
- reads and writes that survive disconnects;
- agent-managed connections;
- Runner work: Grok support and controller recovery;
- the boxd sandbox provider;
- skill packages moving out of Postgres.

The rest is evals and E2E, about 20 performance commits, and 36 migrations, almost all of them indexes.

### Larger new features

- **Coordinator workspace** (`71f0c0c99`, #17983).
  - **What it is:** a per-person, default-off workspace (Settings > Experimental).
  - **What it has:** one conversation per agent; task proposals from chat (new tasks default to the
    chat's agent); compact task and decision cards; document panels; and a Needs You queue with
    search, filters, grouping and history.
  - **New API:**
    - `GET /issues/:id/pending-questions`, `/decision-receipts`, `/chat-handoffs`;
    - `/documents/:key/revisions/:revisionId`;
    - `GET /companies/:companyId/attention/history`;
    - `GET/PUT .../workspace-preferences/me`.
  - **Migrations:** 0404 and 0405.
- **Agent YAML configuration editor** (`b14e1ecaf` #18036, follow-up `cc6a3296e` #18168).
  - A new Advanced agent tab edits a `paperclip/v1` agent document through the existing resource
    APIs, with `expectedConfigurationRevision` for stale writes.
  - It adds CodeMirror 6 and `yaml` to `ui/package.json`; no major-version bumps.
- **Disconnect handling** (`39279aa34` #15754 for reads, `d30c8f42b` #17960 for writes).
  - Error classification, one connection store and banner, and cached data kept during outages.
  - Writes are replayed with their original account, task and request key. Comment and task
    creation use idempotency keys.
  - Adds an `X-Paperclip-Receipt-Only` header for receipt recovery.
- **Live transcript interests** (`6cc765bd8`, #17456).
  - An additive WebSocket negotiation, so transcripts go only to the views that asked for them.
  - Other views get a throttled `heartbeat.run.activity`.
  - Delivery is capped at 1,000 items / 1 MiB.
- **Runtime activity events** (`80a2b9284` #18129, `27be85904` #18050): a `runtime.activity.recorded`
  event and a Runner helper for plugins and runtimes.
- **Connections within delegated authority** (`13709b4c7` #17737, `0c9d10d69` #17739).
  - Authorized agents can configure tool, chat/email, GitHub/Slack, AI, profile and gateway
    connections, with responsible-user audit records.
  - Saved AI sign-in setups can be resumed (`GET .../ai-connections/login/:sessionId/setup`).
  - Migration 0380.
- **Runner controller recovery and remote agent adoption** (`0a08d37aa` #17097, `09ad9adce` #17439).
  - Encrypted checkpoints let a restarted server adopt running remote agents.
  - Migration 0394 adds `native_runner_checkpoints`.
- **Skill packages out of Postgres** (`f1911a4c5`, #18082).
  - Skill repository packages become verified archives in object storage, with local caches and
    30-day expiry for unused ones.
  - Migration 0415 adds `skill_package_deletions` and new columns on
    `company_skill_repository_snapshots` and `company_skill_versions`.
  - The versions list now omits file contents.
- **Hot-upgrade readiness** (`567c043b1`, #18037): `GET /api/instance/task-drain?upgradeReadiness=1`.
- **Grok on Paperclip Runner** (`f60ac29cf` #17922 and others): `paperclipRunnerProfileForHarness`
  maps `grok_local` to ACPX `grok` (Linux x64, macOS arm64).
- **boxd sandbox provider** (`644937c93`, #17284).
- **Smaller additions:**
  - reuse of prepared Runner storage (`c57af3c56`) and of verified workspace seeds (`27fbdb2a7`);
  - QA smoke journeys (`b81b87073`);
  - eval report features.

### Live socket

`ui-new/src/lib/live-events.tsx` handles a server close (1013) the same as any other close:
- `onclose` starts the polling fallback and schedules a reconnect with backoff (1 s, doubling, capped);
- `onopen` resets the backoff, stops polling and refreshes every active query.

So the new backlog close is covered. The events lost before reconnect are made up by that refresh.
No change was needed beyond handling the new event type.
