U168 detail:

- **The old UI's bug:** it decided which messages were still queued from each run's start inputs,
  so once the live queue closed, a message the first turn took looked queued again.
- **Why ui-new is unaffected:** its strip and thread hide only the server queue's own entries
  (`visibleEntries`, `queuedIds`), and the first-turn set comes from the live queue. Once the
  server queue is empty, those messages stay in the thread at their send time.

operator-only.
