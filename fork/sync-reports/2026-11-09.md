## Upstream changes

**196 upstream commits** (`f6cb3e43f..3ef45fdd9`, 2026-11-07 – 2026-11-09)

Most of this batch makes restart recovery sturdier. About 70 commits move every kind of lease, claim
and lock onto one "proven-gone owner" path (three migrations come with it), and runs, turns and queued
messages now survive a server restart. Agent guidance is the next largest group, about 33 commits:
board-only refusals are now final, and they link the board page that holds the control. Board-facing
changes are few: queued follow-ups are steered into the live turn after 5 seconds, a parent task shows
its stalled children with their Retry, a waiting Retry names the blockers it waits on, the board can
confirm that an unrecorded owner stopped, and deleting an environment warns about kept failed-run
copies.

### Larger new features

- **Queued follow-ups are steered into the live turn automatically** (`4aed3056d`, #19970). After a 5 s edit window, a person's own plain queued message is steered into the running turn. The row reads "Sending in Xs" with Edit and Cancel. This only happens when `steeringDisposition` is `available` on `paperclip_runner_v1` (Codex and Pi), never for request-card answers or fresh-session entries, and each revision gets one attempt. Steer and Interrupt stay as buttons. It's always on: `TaskChatThread`/`IssueChatThread` default `queuedMessageAutoSteerDelayMs` to 5000, with no flag. Related changes:
  - A steered message that a restart lost is delivered again (`f755361ff`, #19962).
  - A run that is still preparing takes the queued messages into its first turn instead of being interrupted. The queue reports `executionWait.reason: "first_turn_pending"` with "The agent is still starting…" (`b54317d3f`, #20168).
- **Stalled children and blockers wake the parent and show on its page** (`c49ab6b9e`, #20098). When a child or blocker stops on a recovery action that needs the board, the waiting agent is woken once per stall (wake reason `issue_blocker_stalled`, migration 0450). The issue detail now carries `stalledDependencies: IssueBlockerStalledWakeContext[]`. The old UI's new `StalledDependencyNotice` reads "A dependency needs the board" and lists each child with its own Retry. It drops a row once that child's status moves on.
- **The board can confirm that an unrecorded owner stopped** (`0746d1203`, #20067; `4f7eee10c`, #20084). Some records were saved before Paperclip stored which server held them. For these, the recovery cause is `ownership_owner_unprovable`, with `evidence.kind` (eight kinds: sandbox lease, legacy controller lease, teardown claim, sandbox creation, runtime-control operation, workspace finalize attempt, finalizer lease, cleanup lease), plus `recordId` and `recordUpdatedAt`. An owner or admin confirms how they checked, with `POST /issues/:id/recovery-actions/confirm-owner-gone` and `{actionId, recordId, stopEvidence, recordVersion?}`, which returns `{recordId, status: "queued" | "released"}`. This is the U63 form extended to every settling kind.
- **Raise and resume continues the stopped work, once** (`5a51a7685`, #20144, migration 0451 `budget_resume_claims`). Resolving a budget incident with `raise_budget_and_resume` now files a Retry for each run the budget stopped, once that run's stop settles. `AgentLifecycleOperation.pauseCause` records why a pause started.
- **Line diff for a pending skill update** (`28e070f8d`, #20155). A new `GET /companies/:companyId/skills/:skillId/update-diff` returns `SkillSourceUpdateDiff`, a per-file unified diff between the installed and latest tracked GitHub revisions. It's API-only, made for agents; the old UI doesn't call it. Skill routes also accept a slug as `skillId` (`a8ab1d3d9`, #19808).
- **Restart recovery on one shared ownership path** (17 `feat(recovery)` commits plus about 50 related fixes). These include `bf3a06707` #19950 (missed by the last outline), `576ba29ff` #19953, `cc072e7c4` #19964, `bf0d45a4d` #19966, `0cb9770d1` #19965, `838e9bf3d` #19978, `dc0534d1b` #19976, `3ff62fc6d` #19980, `ada44a669` #20006, `2aac7d29f` #20015, `b6f58dc6e` #20016, `20cc6faca` #20017, `484170d13` #20018, `82a1fda9b` #20022 and `e8a3f1f6f` #20054. Each lease or claim records its holder process. A shared prover settles it once that holder is proven gone. A fenced controller epoch (`controller_instances`, migration 0449) proves a replaced container's records gone. Retained orphan sandboxes are destroyed once nothing references them. This is server-only, except where it surfaces as the confirm-owner-gone card above.
- **Board-only refusals are final and link the board control** (`43fe87795`, #20151, followed by about 20 guidance commits). Agents get a refusal that says it's final, names who can act, and links the page: plugin settings by key, an agent's API keys, permissions, budget, identity or runtime tab, `/activity/budgets`, a project's access settings, `/apps/gateways`, `/apps/byo`, Assistant connections, Experimental settings, and Pause subtree under More task actions. These are agent-facing only, but they set which board addresses agents now write.
- **Paperclip's own worktree setup no longer runs before every agent turn** (`a3a25ce6c`, #20269). `scripts/provision-worktree.sh` was renamed to `scripts/setup-paperclip-worktree.sh`, so managed worktrees of the Paperclip repo no longer install dependencies by default. To opt in, set it as the project's `provisionCommand`.
