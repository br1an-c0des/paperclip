## Upstream changes

A small, mostly server-side batch: recovery and wake-queue fixes and performance, saved sessions,
the Runner and native runtime, and the release pipeline. One board-facing feature (pull request link
status cached in the database and shown on page load), a Claude ACP fix the deployed instance hit,
and three small old-UI fixes.

### Larger new features

- **Pull request link status from a database cache** (`f33c4cf6f`, #21746): link previews are
  stored in a new `link_previews` table (migration 0489, per company, viewer and link). A new
  board-only read, `GET /companies/:companyId/link-previews/cached?url=…` (up to 50 links, never
  contacts GitHub), lets the old UI show the status mark of every pull request link on page load,
  then refresh the rest on browser idle (3 at a time, at most 200 per page). `GET …/link-preview`
  is now rate-limited (600 per company and viewer, then 429 with `Retry-After`). Not behind a flag.

### Bug fixes

- **Agents, Runner and native runtime:**
  - **A Claude reply that quotes "Please run /login" no longer fails the run** (`fb288f566`,
    #21921). The patched Claude ACP bridge (`claude-agent-acp` 0.73.0) treated any result text
    containing "Please run /login" as a sign-in failure, even with `is_error: false`, and the run
    failed with "ACP agent reported a terminal access failure." Now only an error result counts
    (a port of claude-agent-acp#1103). Applies to `claude_local` on ACP and the Runner's ACPX
    Claude profile. This is the bug the deployed instance hit.
  - Managed GitHub access survives a controller restart (`cc9ff75cb`, #21928).
  - Tool progress events are batched with text deltas, so tool-heavy turns stop failing on run-row
    lock conflicts (`030810853`, #21533).
  - Only the overflowing call is rejected when parallel tool calls exceed the result reserve
    (`3452639a8`, #21913).
  - A finished warm owner's retained Runner is stopped when suspend is refused (`d149e3032`, #21853).
  - Saved sessions survive config edits the provider thread can't see (`db73178bc`, #21862).
- **Tasks, wake queue and dispatch:**
  - Stop pressed during preparation is confirmed once preparation settles, with no failed-attempt
    notice (`c8dd2e400`, #21906).
  - A person's comment merged into a system wake reopens a finished task (`20b0d4e5a`, #21914);
    the child-completion reason survives such a merge (`93111b175`, #21918).
  - A task tree a person created starts work in the person tier (`4da6902cb`, #21916).
- **Recovery:** a running run stays visible when a dropped continuation is newer (`5561a4068`,
  #21907); an agent configuration write no longer re-checks every task (`94cb7ad35`, #21861).
- **Connections:** satisfied "Connect" cards are retired on blocked and not-started tasks too,
  without waking the agent (`537b0408b`, #21940).
- **Old UI:** Recents tasks stay ready to open from cache (`698c371b1`, #21904); recent task status
  icons aligned, fold controls moved right (`991f773d7`, #21859); a space after composer
  autocomplete (`29903bed5`, #21754).
- **Release, evals and e2e:** 3 commits (`0e8447fe7`, `f7a3497e9`, `77ddf260b`).
